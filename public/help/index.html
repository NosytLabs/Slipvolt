Get your first response

Start at the access card. Before buying anything, check the published Solana mint, holding requirement and funded allowance. An unconfigured mint is not a token launch.

  1. Connect a supported Phantom or Solflare wallet. Check the site address and sign the login message. It is not a transaction or token approval.
  2. Once holdings qualify, select Get API key. Save the key in a password manager; its full value is shown once.
  3. Choose a model, use a small output budget for your first prompt, and send. Or open Use the API for model-aware curl, Python and JavaScript examples.

You do not need your own GNK wallet or OpenBroker account for holder access. The operator manages upstream funding. Never enter an obk- key, wallet private key or seed phrase here.

Wallet not detected? Unlock your supported extension and reload. Mobile-wallet browser interoperability still needs live testing; this release does not promise WalletConnect support. A rejected or expired signature can be retried by starting a new sign-in.

Connect an app

Use the service’s own deployed origin with /v1 as your SDK base URL—not the OpenBroker website or its upstream API. Use your customer sv_ key. No production domain is established by this example.

export SLIPVOLT_BASE_URL="https://YOUR_DEPLOYED_HOST/v1"
# Set SLIPVOLT_API_KEY privately in your server environment.
curl "$SLIPVOLT_BASE_URL/models"

Save this as request.json, using a model ID returned by the live catalog:

{
  "model": "MiniMaxAI/MiniMax-M2.7",
  "messages": [{"role": "user", "content": "Explain an API in one sentence."}],
  "max_tokens": 1024,
  "stream": false
}
curl --fail-with-body -sS "$SLIPVOLT_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $SLIPVOLT_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @request.json

Keep application keys on your server, not in a public frontend bundle or repository. The playground holds its key temporarily in the current page; it is not a hosted key vault. SDK examples on the app disable automatic paid-request retries where applicable.

Models and API support

The documented catalog contains MiniMaxAI/MiniMax-M2.7, deepseek-ai/DeepSeek-V4-Flash-0731 and zai-org/GLM-5.3-Flash. Use the model picker for current availability. A listed model has not necessarily passed a funded inference test.

Understand the allowance

AI tokens are text-processing units, not the Solana coins you hold. Input includes the conversation and tool definitions sent with each call. Input and output count together against the wallet allowance.

The daily window resets at 00:00 UTC, with no rollover. Unresolved reservations remain held across the reset until reviewed. Every key belonging to the same wallet shares its quota. Other users can exhaust the global daily or funded pool before your personal cap is reached.

Context is the model’s input-plus-output window, not an included amount of compute. The request must also fit the remaining allowance, global pool, GNK funding and concurrency limits. Admission uses a conservative byte estimate, so a request can be rejected before an exact tokenizer would fill the advertised context. Prompts are not silently shortened.

Repository defaults are 4,096 output tokens, a 16,384 local output ceiling, 30 requests/minute and 4 concurrent requests per wallet. Model and operator caps can be lower. The configured body limit is 10 MiB by default, with at most 2,048 messages and 5 choices; requesting multiple choices reserves an output budget for each.

Read the current policy card and configured service status, rather than treating these defaults as an upstream capacity guarantee. Start with one request at a time. Check Retry-After before retrying a 429.

Included access and pricing

No checkout or automatic overage billing is enabled in this build. Eligible holders use an operator-funded allowance. A token purchase does not buy a prepaid dollar balance, and an exhausted allowance does not silently turn into a bill.

The proposed metered rate card defaults to $0.075 per million input and $0.30 per million output. These are planning rates, not a subscription or a promise of permanently fixed prices. The app displays configured values.

Reference charge = input_tokens / 1,000,000 × input_rate
                 + output_tokens / 1,000,000 × output_rate

800,000 input + 200,000 output at the proposed defaults
= $0.06 + $0.06 = $0.12

At that mix, 1 billion total tokens represents $120 of hypothetical metered revenue—not $120,000. Included holder usage is not automatically revenue. Provider costs, retries, epoch charges, hosting and other operating expenses still have to be paid.

There is no universal “50% cheaper” promise. Compare the same input/output mix, cache treatment, time-based rate, model version and service limits. DeepSeek’s direct reference in this repository is not the same model revision as the OpenBroker model; lower pricing does not establish identical service.

Fix a failed request

Read the message as well as the status code
ResponseNext step
400 / 422Check the exact schema, model ID and output cap. Remove unsupported fields; do not resend the same invalid body.
401Use a valid customer key. A cookie-only account endpoint instead needs wallet sign-in.
403Check holdings and wallet status. Selling below the threshold blocks new calls once finalized holdings reflect it.
409The key has already used that Idempotency-Key. This is duplicate protection, not a replay of the previous response.
413Reduce the payload. A body-size limit and a model context limit are different constraints.
429Read Retry-After. Daily quotas need the UTC reset; concurrency needs an in-flight call to finish; upstream capacity needs bounded backoff.
502 / interrupted streamThe provider outcome or cost may be uncertain. A reservation can remain held. Record the request ID and seek review; do not retry blindly.
503Read the cause: maintenance, funding, catalog verification, capacity or reconciliation. Buying more project tokens does not repair an operator funding outage.

Record X-Request-Id when present and the completion body’s id. Some failures happen before an ID is assigned. An SSE error may include error.request_id. Stopping the browser request does not prove the provider stopped computing or incurred zero cost.

Use one unique Idempotency-Key per intended operation per API key. It blocks duplicate dispatch after a reservation exists; it does not provide exactly-once execution or cached response replay. Do not rotate keys or change that value merely to bypass an uncertain result.

Keys, sessions and usage

Lost key: create a replacement after signing in, update your app, and revoke the old key. Existing full secrets cannot be retrieved.

Leaked key: revoke it immediately, or use Revoke all API keys. Apps using revoked keys lose new-request access; accounting history is retained. Calls already dispatched may finish.

Shared computer: use Sign out all devices to end browser sessions. This does not revoke API keys. Disconnecting a wallet extension by itself does not necessarily remove the site session.

Download recent usage (CSV) after wallet sign-in. The export contains the latest 100 records, not a full account archive. Holder cost columns are in ngonka: 1 GNK = 1,000,000,000 ngonka. Estimated reservations are not settled cost or a customer bill.

Token and funding boundaries

Holding qualifies a wallet for finite access; it is not staking, an on-chain API-key mint, a GNK redemption claim or a treasury share. Tokens stay in your wallet. The build has no staking contract, token checkout or automatic buyback.

Native GNK funds upstream inference. WGNK on Ethereum and the project’s Solana token are different assets. Do not send SOL or SPL tokens to a Gonka deposit address. Swap tools and launch venues mentioned in research are not integrated purchase or deposit instructions for customers.

The operator may replenish compute from collected creator fees or other revenue. Market capitalization and unclaimed fees are not spendable cash. See the proposed funding and developer policy. Global OpenBroker statistics are network-wide, not Slipvolt users, revenue or uptime.

Get help safely

For non-sensitive software bugs, use GitHub issues. Include the page, steps to reproduce, time in UTC, HTTP status, model ID and a sanitized request ID when available. Check that a report contains no sensitive data before making it public.

Never publish API keys, authorization headers, cookies, private RPC URLs, seed phrases, private prompts or unredacted usage exports. A private security/account-support channel and response-time policy have not yet been published. Do not post exploit details or personal account disputes in public issues; launch requires a private contact first.

Operator references: launch content checklist · OpenBroker documentation · upstream status. An upstream status page is not an end-to-end Slipvolt uptime guarantee.
