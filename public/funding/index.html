Holding unlocks access; it does not fund a personal account

A qualifying wallet can receive the configured service allowance while it remains eligible. Tokens stay in the wallet in the implemented holder flow. More API keys do not multiply quota, unused daily allowance does not roll over, and buying a market token does not create a refundable service deposit.

The project mint, threshold and effective limits must be published before launch. An empty configuration or a ticker without a verified mint is not an invitation to buy anything.

OpenBroker funding is an operator responsibility

The operator acquires native GNK into an owner-controlled account, then funds the deposit address assigned by the dedicated OpenBroker dashboard. A registration wallet, public operator address, self-custody reserve and dashboard deposit address are different values; copying the wrong one can lose funds.

Slipvolt checks spendable provider credit before dispatch and maintains a separate local allowance ledger. An admin allocation only mirrors funds the operator has already verified; it does not move GNK. The reservation rate is a conservative admission estimate, and final provider cost can exceed it.

Acquisition and bridge routes are not customer instructions

The repository records dated operator research about native-GNK acquisition and the official WGNK return bridge. Those routes, fees and availability can change. Before moving operating funds, the operator must re-check the current primary documentation, exact asset and destination, custody requirements, minimum received and final on-chain result.

The documented WGNK return flow derives the native receiving account from the same signing key used for the Ethereum burn. It is not a general arbitrary-recipient swap. Customers should not send SOL, SPL tokens, WGNK or any other asset to a Gonka or OpenBroker address shown in product documentation.

Project revenue is not guaranteed

Realized creator fees or future earned service revenue may replenish compute after operating costs and obligations. Trading volume, market capitalization, unclaimed fees, unsold team tokens and user lock principal are not spendable revenue. Zero trading produces zero creator-fee income while service costs can continue.

Launch venues, fee recipients, optional burns and developer distributions remain proposals described in dated token design research. None is an entitlement for holders or an automated action in this application.

What the software does not do

The public server holds no treasury signing key and cannot execute a swap, bridge, token launch, creator-fee claim, buyback, burn or developer payout. It does not accept customer token payments or credit transfers as service balances.

Operator references: Gonka GNK/WGNK FAQ · Gonka bridge overview · OpenBroker documentation. Re-check them before any transfer; a repository snapshot is not a live quote or deposit authorization.
