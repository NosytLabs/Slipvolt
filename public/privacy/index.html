What this notice covers

This is a prelaunch technical disclosure for this repository, not a completed production privacy policy. The deployed operator’s identity, private contact, retention periods and hosting arrangements must be published before customer onboarding.

Wallet sign-in is not anonymous. Public blockchain activity and service records can link requests to a wallet. A login without email is not a promise of anonymity.

Data the application handles

  • Account and security: wallet address, one-time sign-in challenge text and expiry, hashed session identifiers, hashed API keys, key prefixes/names, creation times and revocation state.
  • Usage and accounting: model, request identifiers, timestamps, token counts, reservations, cost estimates or confirmed costs, and settlement/review state.
  • Operations: IP-derived hashed rate-limit buckets, administrator actions, wallet-policy notes, reconciliation evidence and business-ledger entries.

The local inference ledger is not designed to store prompt or completion bodies. Requests still pass through the application in memory and are sent upstream. Operator-entered notes and evidence can retain whatever text is entered: do not put secrets or private prompts in them.

Where requests go

Prompts, conversation history and tool definitions are processed through OpenBroker and the Gonka network. The configured Solana RPC provider receives wallet/mint queries for holder verification. Hosting, proxies and wallet extensions have their own processing and logging behavior.

This is not an end-to-end zero-retention guarantee. Upstream training, retention, subprocessors, processing locations and contractual protections have not been independently verified here. Do not submit confidential or regulated data without reviewing the deployed service and upstream terms.

Public network widgets use aggregate statistics. A configured native GNK reserve address is public; publication of the separate OpenBroker service balance is optional. Neither is an individual customer redemption balance.

Cookies and browser data

gridraft_session is the required sign-in cookie. The code sets HttpOnly and SameSite=Strict; Secure is enabled in production mode. The existing cookie name is retained for compatibility even when display branding changes.

The customer interface does not persist API-key secrets in localStorage or sessionStorage. The current page and your clipboard may contain a copied key. Closing a page is not key revocation. These documentation pages include no analytics scripts, third-party embeds or input forms; deployment-level services may add their own logging.

Control and retention

Revoke keys, end browser sessions and export recent usage through account controls. The export is limited to the latest 100 records. Revocation and sign-out do not erase billing records.

There is no self-service account deletion in this build. No fixed deletion or retention schedule for usage records, operator notes, host logs or backups has been approved. Before launch, the operator must publish those periods, a private request channel, and a verified deletion/export process. Do not put privacy requests in public GitHub issues.
