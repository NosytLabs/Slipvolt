Scope

This is a prelaunch technical disclosure, not a completed production privacy policy. Before onboarding customers, the operator must publish its identity, private contact, retention periods, hosting arrangements, and applicable legal terms.

Wallet sign-in is not anonymous. Public blockchain activity and service records can connect requests to a wallet address. Signing in without email does not prevent that link.

Records kept by this application

  • Account and security: wallet address, sign-in challenge and expiry, hashed sessions, hashed API keys, key names and prefixes, timestamps, and revocation state.
  • Usage and accounting: model, request ID, token counts, timestamps, reservations, cost estimates or confirmed costs, and settlement state.
  • Operations: IP-derived hashed rate-limit buckets, administrator actions, policy notes, reconciliation evidence, and business-ledger entries.

The inference ledger is not designed to store prompt or completion bodies. Requests still pass through application memory and go upstream. Operator notes can retain entered text, so do not place secrets or private prompts in them.

Other processors receive parts of a request

Prompts, conversation history, and tool definitions pass through OpenBroker and the Gonka network. The configured Solana RPC provider receives wallet and mint queries. Hosting, proxies, and wallet extensions can keep their own logs.

This is not an end-to-end zero-retention guarantee. Upstream training, retention, subprocessors, processing locations, and contract terms have not been independently verified here. Do not submit confidential or regulated data until you review the deployed service and its upstream terms.

Browser data

gridraft_session is the required sign-in cookie. The name remains for compatibility during the Holdbyte display-brand migration. The cookie is HttpOnly and SameSite=Strict; production mode also sets Secure.

The app keeps prompts, answers, and customer API secrets in this tab’s memory, not in localStorage or sessionStorage. Sending a follow-up sends the retained conversation to the model again. Downloaded chats and answers are files on your device. Start new chat clears this tab’s conversation; wallet or customer-key changes also clear it. A key can remain in the current page or clipboard until you clear it. Closing a tab does not revoke the key. These guides contain no analytics scripts, third-party embeds, or forms, though deployment infrastructure may add logs.

Your controls and current limits

You can revoke keys, sign out browser sessions, and export the latest 100 usage records from the account controls. Revocation and sign-out do not erase accounting records.

There is no self-service account deletion and no approved deletion or retention schedule for usage, operator notes, host logs, or backups. The operator must publish those periods and a private request process before launch. Do not post a privacy request in a public GitHub issue.
