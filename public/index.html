API POLICY
Know your limits.
Local limits · upstream support must be tested
OUTPUT
4K default · 16K max
Normal requests default to 4,096 output tokens. You can request up to 16,384 when the selected model advertises that capability.
CONTEXT
180K–400K
MiniMax M2.7 currently advertises 180K context. DeepSeek V4 Flash and GLM 5.3 Flash advertise 400K. These are Gonka metadata values, not an OpenBroker performance guarantee. Input plus requested output must fit; conservative byte-based checks may reject earlier.
RATE LIMIT
30 RPM · 4 concurrent
Initial per-wallet defaults. Limits return standard 429 responses with Retry-After and can be tuned by the operator as real capacity is measured.
PLANNED OVERAGE
$0.075 in · $0.30 out / 1M
Reference retail pricing for future metered usage. Holder allowance is funded separately; checkout/overage billing is not enabled in this build.

What exactly does holding unlock?+
A maximum daily allowance of AI input and output tokens, shared across your API keys. The Solana coins stay in your wallet. Daily and shared-pool caps still apply, and service pauses when funding or capacity is unavailable. The final threshold will be published before launch.
What happens when I sell?+
Holdings are checked again before each new API request. Below the required amount, your key cannot make new calls. Calls already in progress may finish. Creating another key does not reset the wallet’s daily allowance.
Where does the GNK come from?+
The operator funds the native-GNK treasury and allocates a finite inference budget. Collected creator fees may replenish it after disclosed operating costs. Swap execution and fee collection are not automated in this build.
How is the developer paid?+
Proposed policy: 70% of distributable surplus to the developer after service costs, customer obligations and reserve replenishment; 30% retained. This is not 70% of token purchases. No payouts are automated.
