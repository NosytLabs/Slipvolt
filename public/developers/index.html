Make your first request

Set the deployed service origin and customer key on your server. Requests go to POST /v1/chat/completions. Older SLIPVOLT_* environment names remain supported by existing integrations, including SLIPVOLT_API_KEY. New examples use HOLDBYTE_API_KEY; the customer key itself still starts with sv_.

export HOLDBYTE_BASE_URL="https://YOUR_DEPLOYED_HOST/v1"
export HOLDBYTE_API_KEY="sv_..."

curl --fail-with-body -sS "$HOLDBYTE_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $HOLDBYTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"MiniMaxAI/MiniMax-M2.7","messages":[{"role":"user","content":"Say hello in one sentence."}],"max_tokens":256}'

Use GET /v1/models for the currently usable catalog. If live verification fails, the endpoint returns an error instead of presenting a saved snapshot as live.

Streaming and function tools

Set stream: true for SSE in holder-allowance mode. Read error events, final usage, and [DONE]; an HTTP 200 alone does not prove the stream completed. Function definitions and returned tool calls pass through, but Holdbyte never executes tools. Validate arguments and authorize every side effect in your application.

Use bounded requests and deliberate retries

Input and output both count against the wallet allowance. Start with a modest max_tokens. Respect Retry-After on 429 responses. Preserve the request ID and inspect usage before retrying an interrupted request because its provider outcome can be uncertain.

Common responses: 401 means the key is invalid; 403 means holder access is unavailable; 429 marks a rate, concurrency, or allowance limit; 502/503 can indicate provider, funding, catalog, or reconciliation state.

Keep credentials separated

Customer apps can name their local secret HOLDBYTE_API_KEY; the API accepts the same existing sv_ key. Keep it out of browser bundles and repositories. The operator’s OpenBroker credential stays server-side. Never paste an obk- key, wallet private key, or seed phrase into the customer app.

See the help guide for account recovery, usage, and detailed error handling. The exact schema is available at /openapi.json.
