Make your first request

Set the deployed Slipvolt origin and your customer key in server-side environment variables. Do not put a key in a public browser bundle.

export SLIPVOLT_BASE_URL="https://YOUR_DEPLOYED_HOST/v1"
export SLIPVOLT_API_KEY="sv_..."

curl --fail-with-body -sS "$SLIPVOLT_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $SLIPVOLT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"MiniMaxAI/MiniMax-M2.7","messages":[{"role":"user","content":"Say hello in one sentence."}],"max_tokens":256}'

Discover the currently usable catalog from GET /v1/models. If live verification is unavailable, that endpoint returns an error rather than pretending a snapshot is live.

Streaming and function tools

POST /v1/chat/completions supports SSE streaming in holder-allowance mode. Standard function-tool definitions and returned tool calls are passed through; Slipvolt does not execute your tools. Your application must validate tool arguments and authorize every side effect.

Use bounded requests

Input and output both consume the wallet allowance. Start with a modest max_tokens, respect Retry-After, and do not automatically retry an interrupted paid upstream request. Use the homepage’s Check request · no inference action before large calls.

Error handling

401 means the customer key or session is invalid. 403 usually means holder eligibility is not satisfied. 429 means a rate, concurrency, or allowance limit is active. 502/503 can indicate upstream, funding, catalog, or reconciliation state. Preserve the request ID and inspect usage before retrying uncertain requests.

Keep credentials separated

Customer applications use SLIPVOLT_API_KEY. The server’s OpenBroker key stays private and is never exposed through the website, connection kit, support report, or examples. Never paste a wallet seed phrase or private key into Slipvolt.
