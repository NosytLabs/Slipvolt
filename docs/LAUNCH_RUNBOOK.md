# Launch gates

1. Identify the exact GitHub destination. Review the local branch/diff against that repository before a merge. No unrelated repo should receive this code by name guessing.
2. Deploy the single-instance backend on persistent storage with HTTPS and privately configured OpenBroker key. Preserve existing pepper/database on upgrade.
3. Read the actual catalog/account balance. Run the explicitly authorized bounded provider smoke check, then measure larger representative tasks, streaming, usage identities, costs, epoch adjustments and rate limits.
4. Obtain native GNK through a currently quoted route and a small owner-approved test. Verify the correct native receiving account. Fund the actual dashboard deposit address and reconcile the receipt. Keep treasury reserve and provider spendable balance distinct.
5. Choose and disclose token rights, holder threshold, daily and global limits, pool exhaustion behavior, developer compensation and launch venue fee rights. No current token mint or final policy is supplied by this build. Use appropriate jurisdictional review.
6. Configure only the real mint and raw threshold. Set a conservative globally funded allowance. Test actual Phantom/Solflare signatures, wallet changes, revocation, selling below threshold, restarts, high concurrency and browser security headers. Do not market the sum of wallet maxima as guaranteed capacity.
7. Resolve cross-wallet transfer/allowance farming before large recurring grants. Set monitoring and operational reserve policies. Do not present manual budget allocations as on-chain deposits or provider network statistics as project adoption.
8. Only after these checks, publish token purchase links and service terms. Nothing here signs a coin launch, claim, transfer, bridge or swap.
